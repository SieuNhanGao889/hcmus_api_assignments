# PB-02 — Xử lý lỗi làm lộ stack trace, đường dẫn tuyệt đối và thông tin nội bộ framework

| Trường | Giá trị |
|---|---|
| `bug_id` | `PB-02` |
| `status` | `CONFIRMED_BY_HUMAN_REVIEW` |
| Mức độ nghiêm trọng | **HIGH** |
| Endpoint bị ảnh hưởng | `POST /api/login`; `PUT /api/admin/orders/:id/status` |
| `case_id`/`scenario_id` bị ảnh hưởng | `LOGIN-GEN-036`, `LOGIN-EXT-005`, `ORDERSTATUS-GEN-033`, `ORDERSTATUS-GEN-035` |

## Yêu cầu/nguồn

- Các security assertion `NO_INTERNAL_LEAKAGE` đã audit cho request body malformed/không được hỗ trợ.
- `docs/api_specification.md` — định nghĩa request body của Login và Admin Order Status.
- Quyết định của người duyệt: xác nhận PB-02 để lập báo cáo lỗi.

## Điều kiện tiên quyết

- Backend đang chạy.
- Với Order Status, cần có admin token hợp lệ và order được kiểm soát.
- Request có `X-Student-Id: 23127364`.

## Các bước tái hiện

1. Gửi JSON malformed tới `POST /api/login`, ví dụ body kết thúc ngay sau `"password":`.
2. Quan sát response body.
3. Gửi JSON malformed tới `PUT /api/admin/orders/:id/status` bằng admin token hợp lệ.
4. Gửi body có hình thức JSON hợp lệ nhưng dùng `Content-Type: text/plain` tới cùng endpoint Order Status.
5. Kiểm tra response status, exception text, stack frame, source path, tên framework và số dòng.

## Kết quả mong đợi

Body không hợp lệ hoặc không được hỗ trợ phải bị từ chối bằng error response được kiểm soát, không làm lộ stack trace, filesystem path, source line, tên dependency, chi tiết SQL hoặc output của exception chưa được xử lý.

## Kết quả thực tế

- JSON malformed trả trang HTML `400` chứa `SyntaxError`, stack frame, đường dẫn workspace Windows tuyệt đối và thông tin nội bộ `body-parser`/`raw-body`.
- Content-Type sai trên Order Status trả HTML `500` chứa `TypeError`, `server.js:526` và các đường dẫn framework/module.

## Tham chiếu bằng chứng Newman

- `reports/newman/login_run.json`: các vòng lặp `35`, `45`.
- `reports/newman/order_status_run.json`: các vòng lặp `32`, `34`.
- `reports/newman/order_status_rerun_after_automation_fix.json`: các vòng lặp `32`, `34`; cả hai assertion về rò rỉ thông tin tiếp tục thất bại sau khi sửa automation.
- Các assertion thất bại: `[LOGIN-GEN-036] no internal details leak`, `[LOGIN-EXT-005] no internal details leak`, `[ORDERSTATUS-GEN-033] no internal details leakage`, `[ORDERSTATUS-GEN-035] no internal details leakage`.
- Tài liệu phân tích: `reports/analysis/newman_execution_analysis.md` và `reports/analysis/order_status_automation_fix_review.md`.

## Tác động bảo mật/nghiệp vụ

Response tiết lộ bố cục server, vị trí source, framework dependency và failure path, có thể giúp attacker fingerprint ứng dụng và chuẩn bị tấn công có chủ đích. Response `500` thô cũng cho client thấy cơ chế xử lý lỗi không ổn định.

## Ghi chú độ tin cậy

Độ tin cậy **cao**: báo cáo chứa bằng chứng trực tiếp trong response body và phần Order Status được tái hiện không đổi trong lần chạy lại sau khi sửa automation. Người duyệt đã xác nhận PB-02 để lập báo cáo lỗi.
