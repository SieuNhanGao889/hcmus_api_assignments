# PB-07 — JWT của user thường có thể cập nhật trạng thái order qua endpoint admin

| Trường | Giá trị |
|---|---|
| `bug_id` | `PB-07` |
| `status` | `CONFIRMED_BY_HUMAN_REVIEW` |
| Mức độ nghiêm trọng | **CRITICAL** |
| Endpoint bị ảnh hưởng | `PUT /api/admin/orders/:id/status` |
| `case_id`/`scenario_id` bị ảnh hưởng | `ORDERSTATUS-GEN-010`, `ORDERSTATUS-GEN-011`, `ORDERSTATUS-GEN-031`, `ORDERSTATUS-EXT-001` |

## Yêu cầu/nguồn

`EShop-source/README.md` FR-12 và SEC-02/SEC-03 yêu cầu `/api/admin/*` kiểm tra cả JWT hợp lệ và `role='admin'`. Người duyệt đã xác nhận PB-07.

## Điều kiện tiên quyết

- User thường dùng một lần có JWT non-admin hợp lệ.
- Order mới được kiểm soát ở trạng thái `pending`; các biến thể bao gồm order của chính user và body có thêm `role/isAdmin`.

## Các bước tái hiện

1. Xác thực bằng user thường và lấy JWT của user đó.
2. Tạo order `pending` được kiểm soát.
3. Gửi `PUT /api/admin/orders/:id/status` với `Authorization: Bearer <normal-user-token>` và body `{"status":"confirmed"}`.
4. Có thể lặp lại với order của chính user và body có thêm `role/isAdmin`.
5. Đọc order bằng verification được cấp quyền và kiểm tra persisted status.

## Kết quả mong đợi

Endpoint admin phải từ chối mọi normal-user token và order phải giữ `pending`.

## Kết quả thực tế

Endpoint trả `200`, `{"message":"Order status updated"}` và order được lưu ở `confirmed`.

## Tham chiếu bằng chứng Newman

- Lần chạy ban đầu: `reports/newman/order_status_run.json`, các vòng lặp `9`, `10`, `30`, `42`.
- Lần chạy lại sau khi sửa automation: `reports/newman/order_status_rerun_after_automation_fix.json`, cùng các iteration tiếp tục fail.
- Các assertion thất bại: `[ORDERSTATUS-GEN-010/011/031] persisted state is unchanged` và `[ORDERSTATUS-EXT-001] persisted state is unchanged`; quan sát `confirmed` thay vì `pending`.
- Review automation: `reports/analysis/order_status_automation_fix_review.md` xác nhận assertion PB-07 được giữ nguyên.

## Tác động bảo mật/nghiệp vụ

Đây là authorization bypass. Bất kỳ user thường đã xác thực nào cũng có thể thay đổi trạng thái workflow của order qua API dành riêng cho admin, ảnh hưởng fulfillment, order khách hàng, tính toàn vẹn audit và có thể cả hoạt động tài chính.

## Ghi chú độ tin cậy

Độ tin cậy **cao**: yêu cầu về vai trò rõ ràng, bốn biến thể được kiểm soát, kiểm tra trạng thái đã lưu và lần chạy lại độc lập sau khi sửa automation đều cho cùng kết quả. Người duyệt đã xác nhận PB-07.
