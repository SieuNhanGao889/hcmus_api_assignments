# PB-05 — Apply-coupon chấp nhận user_id dạng object và vẫn cấp giảm giá hợp lệ

| Trường | Giá trị |
|---|---|
| `bug_id` | `PB-05` |
| `status` | `CONFIRMED_BY_HUMAN_REVIEW` |
| Mức độ nghiêm trọng | **HIGH** |
| Endpoint bị ảnh hưởng | `POST /api/apply-coupon` |
| `case_id`/`scenario_id` bị ảnh hưởng | `COUPON-GEN-025` |

## Yêu cầu/nguồn

- `docs/api_specification.md` Coupons 5.1 mô tả `user_id` là định danh scalar thông thường trong request body.
- Mục tiêu security đã audit: input object-operator không được thao túng usage hoặc logic coupon cross-user.
- Người duyệt đã xem xét rõ hành vi quan sát được và xác nhận PB-05 để lập báo cáo lỗi.

## Điều kiện tiên quyết

- User dùng một lần đã xác thực bằng JWT hợp lệ.
- Coupon cố định được kiểm soát đang hoạt động và thỏa các quy tắc đủ điều kiện khác.

## Các bước tái hiện

1. Gửi `POST /api/apply-coupon` với coupon code và total amount hợp lệ.
2. Thay `user_id` scalar bằng object `{"$gt":0}`.
3. Giữ Authorization header hợp lệ của user.
4. Kiểm tra API từ chối type hay trả giảm giá hợp lệ.

## Kết quả mong đợi

API phải từ chối an toàn `user_id` dạng object; không được trả kết quả apply coupon thành công hoặc giảm giá hợp lệ cho identity không phải scalar.

## Kết quả thực tế

Response là `200` với `success=true`, `discount_amount=50000` và `final_amount=450000`.

## Tham chiếu bằng chứng Newman

- `reports/newman/coupon_run.json`, vòng lặp `24`.
- Request chứa `"user_id":{"$gt":0}`.
- Assertion thất bại: `[COUPON-GEN-025] no valid discount is returned`.
- Phân tích bằng chứng: `reports/analysis/newman_execution_analysis.md`, PB-05.

## Tác động bảo mật/nghiệp vụ

Thiếu validation type cho identity có thể phá vỡ điều kiện theo user và việc tính usage limit, đồng thời cho phép lạm dụng business rule hoặc apply giảm giá cross-user.

## Ghi chú độ tin cậy

Phân loại lịch sử của AI vẫn là `POTENTIAL_SUT_BUG` với độ tin cậy **Medium** vì specification không có bảng type/rejection đầy đủ. Tách biệt với đánh giá đó, human đã review request dùng object nhưng vẫn thành công và đặt trạng thái báo cáo cuối cùng là `CONFIRMED_BY_HUMAN_REVIEW`. Độ tin cậy lịch sử của AI không bị viết lại.
